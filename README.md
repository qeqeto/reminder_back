# APA Reminder: backend
API + Telegram ბოტი + cron სკრიპტი. Root Directory არ სჭირდება: repo-ს ძირში არის package.json.

## Railway
**API სერვისი:** New → GitHub Repo → ეს repo. Variables:
```
DATABASE_URL=${{Postgres.DATABASE_URL}}
JWT_SECRET=...
ADMIN_EMAIL=...
ADMIN_PASSWORD=...
FRONTEND_URL=https://<frontend-domain>
```
Settings → Networking → Generate Domain.

**Cron სერვისი:** New → GitHub Repo → იგივე repo. Variables: `DATABASE_URL`, `ADMIN_EMAIL`.
Start Command: `npm run cron`, Cron Schedule: `*/10 * * * *` (ყოველ 10 წუთში; ვადებს საათები და წუთები აქვს).

SMTP და Telegram ტოკენი ადმინის პანელიდან ემატება.

## რეგისტრაცია და ვერიფიკაცია
- ახალი მომხმარებელი თვითონ რეგისტრირდება (`/api/register`) და ანგარიში დაუდასტურებელია.
- თუ SMTP გამართულია (ადმინის პანელი → პარამეტრები), მეილზე მიდის 6-ციფრიანი კოდი (10 წუთი, მაქს. 5 ცდა, ახალი კოდი 1 წუთში ერთხელ).
- თუ Telegram ბოტია მიერთებული, მომხმარებელი QR კოდით/ბმულით გადადის ბოტთან (`/start v_<ერთჯერადი ტოკენი>`) და ანგარიში მაშინვე დასტურდება. ამავე დროს Telegram შეხსენებებიც ეკავშირება.
- თუ ორივე გამორთულია, ადმინი ადასტურებს ხელით (მომხმარებლების გვერდი).
- `/api/health` გვერდით შეგიძლია შეამოწმო, მუშაობს თუ არა API.

## დავალებები
- ვადა = თარიღი + დრო (თბილისის დროით). ახალი დავალების ნაგულისხმევი ვადაა ახლიდან 10 დღე.
- შეხსენებები: 7/3/1 დღით, 2/1 საათით ადრე ან ვადის დადგომისას (თითო დავალებაზე ირჩევა).
- ერთმა მონიშნულმა პირმა (ან შემქმნელმა/ადმინმა) შეიძლება დავალება შესრულებულად მონიშნოს, მაშინ ყველასთვის დასრულდება. ჩანს, ვინ და როდის შეასრულა.
- გადადება: +1 საათი / +1 დღე / +3 დღე / +1 კვირა ან ახალი თარიღი და დრო. ვადის შეცვლისას შეხსენებები თავიდან დაითვლება.
- ძველი ვადები ბაზაში 18:00-ზე გადავა (თბილისის დროით).

## დავალების შექმნა ბოტიდან (Mini App)
ბოტში `/new` (ან მენიუს ღილაკი „ახალი დავალება") ხსნის ფორმას: სახელი, ვადა (თარიღი და დრო), შეხსენებები, ხალხის ჩექბოქსები, „გაუგზავნე ახლავე". საჭიროა:
- `FRONTEND_URL` backend-ზე უნდა იყოს `https://...` და frontend-ზე უნდა იყოს `tg.html`;
- მომხმარებელს Telegram უნდა ჰქონდეს დაკავშირებული (ავტორიზაცია Telegram-ის ხელმოწერილი initData-ით).

## დამტკიცება და უცნობი გამგზავნები
- რეგისტრაციის შემდეგ მომხმარებელმა ჯერ ვერიფიკაცია უნდა გაიაროს (ელფოსტა ან Telegram), შემდეგ ადმინმა უნდა დაამტკიცოს (მომხმარებლების გვერდი). დამტკიცებამდე შესვლა, შეხსენებები და ბოტი მიუწვდომელია.
- ადმინის მიერ დამატებული და ძველი მომხმარებლები დამტკიცებულად ითვლებიან.
- Telegram ბოტი ყველა შეტყობინებას, რომელიც ბაზაში არსებული ანგარიშიდან არ მოდის, სრულად უგულებელყოფს და პასუხს არ აგზავნის. `/new` და Mini App მხოლოდ დადასტურებული და დამტკიცებული მომხმარებლისთვისაა.
